# Prompt / brief for the developer: fix canonicals and llms.txt (CRITICAL)

**Problem:** `layout/theme.liquid` in theme "DiggerLid-Web/main" contains a block marked `{%- comment -%}dl-bc-v2{%- endcomment -%}`. It outputs:

```liquid
{%- if template contains 'product' and product.metafields.deeplumen.ap_deployed.value == true -%}
  <link rel="canonical" href="https://{{ request.host }}/a/shop/products/{{ product.handle }}">
{%- elsif template contains 'collection' and collection.metafields.deeplumen.ap_deployed.value == true -%}
  <link rel="canonical" href="https://{{ request.host }}/a/shop/collections/{{ collection.handle }}">
... (same for articles: /a/shop/blogs/<blog>/<article>)
{%- else -%}
  <link rel="canonical" href="{{ canonical_url }}">
```

`/a/shop/...` URLs return 404 for every user agent, including Googlebot. As of 8 Oct 2026, all 49 product and collection pages carry this canonical. `/llms.txt` (likely generated by the same DeepLumen app) describes DiggerLid as "lids for excavator buckets" and links to the 404 URLs.

**Fix:**
1. Confirm with Matt whether the DeepLumen app should stay. If not, uninstall it.
2. Replace the whole block with `<link rel="canonical" href="{{ canonical_url }}">`.
3. Remove or replace `/llms.txt` with an accurate summary that links to real `/collections/` and `/products/` URLs.
4. Verify with `curl -s https://diggerlid.com/products/pro-mat | grep canonical`. It should return `https://diggerlid.com/products/pro-mat`.
5. Request reindexing in Search Console for the top products and collections.
